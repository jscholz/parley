# Parley ↔ Hermes coupling audit

Read-only audit of `/home/jscholz/code/parley` at `33c22a7` (2026-10-25). Every claim carries a `file:line`; nothing was run, built or modified.

## Verdict in one paragraph

The structure is right and the slogans are true: `src/` never talks to Hermes, `proxy/` reaches the agent only through `/v1/*`, and the optional-extension pattern (404 → `null` → hidden UI section) is applied cleanly to settings, jobs, health, commands, search and the gateway drawer. What has rotted is the *behavioural* boundary: the shape of the upstream contract is defined in **seven places that disagree** (two divergent `ParleyEnvelope` unions, a hand-maintained `FANOUT_TYPES` allow-list, the plugin docstring, the Playwright mock, the FakeAgent, and a protocol doc that covers 8 of ~22 route families), and Hermes gateway **prose** (cron wrapper text, approval wording, heartbeat text, memory-context tags, attachment notes) is matched by regex in nine PWA/proxy files. That drift has already produced two real defects (the proxy silently drops the plugin's `job_run` and `activity_changed` envelopes; the proxy push preview only matches the pre-0.21.5 approval wording) and one structural dead end (a second, in-process upstream cannot serve unread/pins/activity/user-settings because `delegate.ts` bypasses the `UpstreamAgent` interface with its own HTTP client). It is not "shambles"; it is a boundary maintained by convention and comments that nobody can verify. A targeted refactor (≈5–8 working days, stoppable after day 3 with most of the value banked) restores a boundary that is *checked*, not just described.

## 0. Method and what "the contract" actually is

Read first: `docs/ABSTRACT_AGENT_PROTOCOL.md`, `docs/ARCHITECTURE.md`, `CONTRIBUTING.md`, `backends/README.md`, `backends/hermes/plugin/README.md`, `proxy/parley/README.md`; then broad greps over `src/`, `proxy/`, `server.ts`, the plugin and the smoke mock; then full reads of `proxy/parley/upstream.ts`, `src/proxyClient.ts` (handleEnvelope), `src/transcript/{types,projection,keys}.ts`, `proxy/parley/stream.ts`, `proxy/parley/notifications/{delegate,dispatch}.ts`, `src/util/progressHeartbeat.ts`, `src/transcript/attachmentNotes.ts`, `src/notifications/approvalText.ts`, the plugin's `__init__.py` route registration and `parley_routes.py`.

Three things the docs say that turned out to be inaccurate and shape the rest of this audit:

1. **`scripts/smoke/mock-backend.mjs` is NOT a mock upstream.** It intercepts the *PWA-facing* `/api/parley/*` surface inside the browser via `page.route()` (`mock-backend.mjs:3-4`, `:252-1737`). The proxy is not under test in any smoke, including the ones named `*-live.mjs` (`cron-run-now-live.mjs:76` calls `mock.finishJobRun`). The only thing that exercises the proxy's `/v1/*` client is `proxy/parley/__tests__/proxy-harness.ts`'s FakeAgent, which implements 9 routes. So there are two de-facto contracts, PWA↔proxy (mock) and proxy↔upstream (FakeAgent), and neither is derived from a shared definition.
2. **`proxy/parley/README.md:469-471` calls the `ParleyEnvelope` union in `upstream.ts` "the canonical list of envelope types fanned out on `/api/parley/stream`".** It is not: `upstream.ts:19-56` lists 14 types; `stream.ts:79-130` fans out 21; `src/proxyClient.ts:799-1150` handles 24; `src/transcript/types.ts:192-209` re-declares 10 "as a mirror". See §1.2.
3. **`delegate.ts:1-9` says "Hermes still uses the legacy in-proxy storage [for push]".** The live unit sets `PARLEY_PUSH_OWNED_BY_PLUGIN=true` (`systemctl --user cat parley.service` line 21) and `PARLEY_INFLIGHT_OWNED_BY_PLUGIN=true` (line 25). The proxy-owned push stack is dead code for the production deployment (§2, leak L5).

Cross-device Activity sync falls back to polling. The protocol doc promises the `job_run` envelope (`ABSTRACT_AGENT_PROTOCOL.md:751-757`), so the doc, the plugin and the PWA agree and the proxy is the odd one out — precisely because the allow-list is hand-maintained with no test that `plugin-emitted ⊆ FANOUT ⊆ PWA-handled`.
* **`backends/claude-code/envelopes.ts:5-10`** still says `agent_question`/`doc_show` are "not yet in that TS union" and defines local copies; they were added to `upstream.ts:40-55` since. Harmless, but it is the third copy of those two shapes.

### 1.3 Graceful degradation — where it is and isn't

Clean (documented 404 → `null` → UI section hides, with a proxy test): settings, jobs, health, commands, search, gateway drawer. That pattern is good and should be the template.

Not clean: items/{item_id}, PATCH rename, push/*, unread/*, pins/*, activity/*, user-settings, questions, upload, auxiliary-models, model-capabilities. These either propagate raw status or return 502. On the in-process `claude-code` upstream (`proxy/parley/index.ts:114-139`) every `delegate.ts` route goes to `http://127.0.0.1:8645` regardless (`delegate.ts:14,83`) — so the badge module, pin drawer, activity tray and synced settings get ECONNREFUSED → 502 on a backend the repo nominally supports. The PWA has no way to learn "this upstream has no pins"; it discovers each feature by probing and swallowing errors.

## 4. Testability and separation

Your CLAUDE.md rule (run on the generation interpreter) exists because of this. Half-hermes-free.
* **Is there one place that defines the contract?** No. Types: `upstream.ts` (envelopes, `ConversationSummary`, `ConversationItem`, `SettingDef`, `CommandDef`, `SearchResult`) with hand-copied mirrors in `src/transcript/types.ts` and `src/proxyClientTypes.ts`.
